# WP-046: Resource Manifest Editor — repair semantic errors and enforce save validity

- **Status:** done
- **Phase:** Resource Manifest Editor validation and repair
- **Priority:** P1
- **Difficulty:** hard
- **Blocked by:** WP-042, WP-045
- **GitHub issue:** [#46](https://github.com/ajare/willpower/issues/46)

## Context

The editor accepted only structural validation as a whole-document gate. Dependency
feedback was partial, file failures were limited to new selections, semantic problems
did not consistently gate saves, and changing the document base could not preserve
file targets.

## Changes

- [x] Open structurally valid documents with semantic errors and report duplicate or
      invalid names, known-reference failures, annotated type mismatches, cycles, and
      annotated file existence, extension, and containment failures.
- [x] Compare each structurally valid edit with the current semantic error set so staged
      repairs can preserve independent errors without introducing unrelated ones.
- [x] Keep standard and schema-annotated selectors constrained to valid new targets and
      avoid interpreting unannotated custom strings.
- [x] Migrate annotated file values atomically when changing base directory while
      preserving canonical absolute targets and rejecting unsafe migrations.
- [x] Gate Save and Save As on complete document validity while allowing warnings.
- [x] Navigate selectable diagnostics to the affected namespace, Resource, and property.
- [x] Add a headless staged-repair regression suite and canonical-output coverage.

## Out of scope

External file conflict handling, recovery, recent files, and final production hardening
remain in the follow-up tickets.
