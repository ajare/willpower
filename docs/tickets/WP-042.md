# WP-042: Resource Manifest Editor — author dependencies and inline Resources

- **Status:** done
- **Phase:** Resource Manifest Editor dependencies
- **Priority:** P1
- **Difficulty:** hard
- **Blocked by:** WP-040, WP-041
- **GitHub issue:** [#42](https://github.com/ajare/willpower/issues/42)

## Context

Resource references were previously displayed only as YAML-owned data. Users could not
select compatible declarations, understand missing targets or cycles, or safely maintain
the inline declarations accepted by the runtime loader.

## Changes

- [x] Present standard dependency references as qualified Resource selectors filtered by
      the built-in dependency's allowed Resource Type.
- [x] Exclude the owner, disable cycle-producing targets, retain unresolved and existing
      inline selections, and clear entries only when structural validation permits it.
- [x] Report unresolved, incompatible, cyclic, and incoming references, and list incoming
      sources when deletion is blocked.
- [x] Display inline dependent Resources beneath their owner; support common rename,
      file, and option edits without exposing independent move operations.
- [x] Promote an inline declaration to a namespace-level Resource and replace it with a
      correctly qualified reference as one undoable command.
- [x] Add headless coverage for filtering, qualification, cycles, missing and incoming
      references, inline selector visibility, editing, and promotion.

## Out of scope

Nested ImageSet and AnimationSet Definition authoring, Program and Material form
rendering, application bundle annotations, and complete semantic save gating remain in
the blocked follow-up tickets.
