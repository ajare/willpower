- **Status:** open

- **GitHub issue:** [#37](https://github.com/ajare/willpower/issues/37)

## Context

The export feature needs an end-to-end acceptance gate proving that an external consumer can obtain built-in and application-owned schemas, compose them without executing application code, and receive the same structural validation behavior as the application runtime. Dynamic schema plugins are optional and are verified separately by WP-036.

## Changes

- [ ] Add an end-to-end downstream fixture containing a custom `Resource` subclass, Resource factory, default definition factory, specialized definition factory, and their schemas.
- [ ] Export the fixture's application-specific bundle and composed root through the supported CMake and command-line paths.
- [ ] Validate representative manifests with both an external schema consumer and `ResourceLocation::scan()` and compare acceptance behavior.
- [ ] Cover top-level and namespaced Resources, singleton/sequence forms, default and specialized Definitions, unknown custom types, collisions, missing references, and incompatible bundle versions.
- [ ] Verify installed-package consumption rather than relying only on Willpower source-tree paths.
- [ ] Document bundle authoring, CMake registration, runtime registration, exporting, editor association, compatibility policy, and security boundaries.
- [ ] Update the Resource Manifest Editor guidance to consume bundles rather than assuming only the built-in root schema.
- [ ] Run the complete CMake/CTest suite on supported Windows and Linux toolchains.

## Acceptance criteria

- A downstream project can build against an installed Willpower package and export one self-contained catalog containing built-in and custom schemas.
- An external process can validate the fixture's Resource Manifests without linking or loading application code.
- Runtime validation rejects the same structurally invalid custom declarations before publishing Resource records.
- Documentation clearly separates structural schema validation from semantic/resource-loading validation.
- Bundle and root-schema output is deterministic and requires no network access.
- The complete test suite passes on Windows/MSVC and Linux/GCC or Clang.
