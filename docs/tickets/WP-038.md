# WP-038: Resource Manifest Editor — validate and round-trip manifests from the CLI

- **Status:** done
- **Phase:** Resource Manifest Editor foundation
- **Priority:** P1
- **Difficulty:** hard
- **Blocked by:** none
- **GitHub issue:** [#38](https://github.com/ajare/willpower/issues/38)

## Context

The Resource Manifest Editor and CI need one bounded document contract that uses the
same immutable Resource Schema Catalog behavior as runtime loading, without exposing
YAML, JSON, or validator implementation objects. The first executable seam must remain
headless and must not initialize SDL or display dialogs.

## Changes

- [x] Add the public, library-neutral `ResourceManifestDocument` parse, validation,
      diagnostic, limit, and canonical-serialization contract.
- [x] Preserve collection order and scalar types while emitting deterministic UTF-8 YAML.
- [x] Add `resource-manager --validate FILE --base-directory DIR` and optional canonical
      round-trip output without platform initialization.
- [x] Distinguish YAML syntax and structural diagnostics while honoring the editor's
      documented stable process codes.
- [x] Enforce manifest size, nesting, node-count, and diagnostic bounds.
- [x] Cover the public API and executable seams through CTest.

## Out of scope

Desktop document workflows, semantic path/resource validation, configurable bundle
loading, editing forms, save/recovery behavior, and GUI initialization belong to the
follow-up Resource Manifest Editor tickets.
