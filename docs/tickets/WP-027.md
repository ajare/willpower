# WP-027: Application — schemas for source-backed built-in Resource Types

- **Status:** open
- **Phase:** Resource Manifest validation — built-in schemas
- **Priority:** P1
- **Difficulty:** medium
- **Blocked by:** [WP-025 / #25](https://github.com/ajare/willpower/issues/25), [WP-026 / #26](https://github.com/ajare/willpower/issues/26)
- **Spec:** `docs/specifications/resource-manifest-schema-validation.md` §§8.1–8.5
- **GitHub issue:** [#27](https://github.com/ajare/willpower/issues/27)

## Context

`TextFile`, `XmlFile`, `Shader`, `AudioBank`, and `Image` are source-backed built-in Resource Types. Their default definition factories accept no payload, while Image also consumes a defined set of Resource options. These declarations should fail during Resource Manifest loading rather than during later creation or loading.

## Changes

- [ ] Add canonical schemas for `TextFile`, `XmlFile`, `Shader`, `AudioBank`, and `Image`.
- [ ] Require a non-empty source `location` while retaining current name inference from location.
- [ ] Permit only empty default Definition payloads for these types.
- [ ] Define Image options and values: `filtering`, `uv-style`, `colour-space`, `wrapping`, and `mipmaps`.
- [ ] Accept compatible native or quoted boolean values for `mipmaps`.
- [ ] Register/embed all five schemas in the built-in schema catalog.
- [ ] Add at least one valid fixture and representative missing-field, unknown-field, invalid-option, null, and malformed-definition cases per schema.
- [ ] Confirm that source-content validation remains creation/load-time behavior.

## Acceptance criteria

- Valid declarations for all five Resource Types load successfully in singleton and sequence contexts.
- Invalid declarations fail from `ResourceLocation::scan()` with a Resource identity and instance path.
- Unknown Image options and unsupported option values are rejected.
- No schema attempts to decode or inspect the referenced source asset.
