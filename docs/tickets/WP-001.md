# WP-001: Common — portable stack walking and unconditional ASSERT_TRACE

- **Status:** done (commit 203a342)
- **Phase:** 1 — Willpower.Common (prerequisite)
- **Priority:** P0 (blocks Linux compilation of Willpower.Application)
- **Difficulty:** medium
- **Depends on:** —
- **Plan ref:** PLAN.md §Phase 1, item 1
- **GitHub issue:** #1

## Context

`StackWalker.h/.cpp` implement a full Win32 DBH/PSAPI stack walker. `WillpowerWalker.h`
defines `ASSERT_TRACE` (and `WillpowerWalker` / `StackWalkerInstance`) only inside
`#if WP_PLATFORM == WP_PLATFORM_WINDOWS`, so on Linux the macro is simply undefined.
`SchedulerTask.cpp` calls `ASSERT_TRACE`, so this is a second-order blocker even after
the Scheduler QPC work (WP-005).

## Changes

- [x] Gate compilation of the Win32 `StackWalker` implementation to Windows.
- [x] Provide a portable `WillpowerWalker` fallback for non-Windows (no-op or `backtrace()`-based).
- [x] Always define `ASSERT_TRACE`; off-Windows it falls back to plain `assert`.
- [x] Keep the Windows behaviour exactly as it is today.

## Files

- `willpower.common/include/willpower/common/StackWalker.h`
- `willpower.common/include/willpower/common/WillpowerWalker.h`
- `willpower.common/src/StackWalker.cpp`
- `willpower.common/src/WillpowerWalker.cpp`

## Acceptance criteria

- `Willpower.Common` compiles on Linux (GCC and Clang) without `StackWalker.cpp` in the build.
- `ASSERT_TRACE` is usable from non-Windows translation units.
- Windows build and stack-walk output unchanged.
