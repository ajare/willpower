# WP-039: Resource Manifest Editor — create, open, and save manifests in the desktop shell

- **Status:** done
- **Phase:** Resource Manifest Editor foundation
- **Priority:** P1
- **Difficulty:** hard
- **Blocked by:** WP-038
- **GitHub issue:** [#39](https://github.com/ajare/willpower/issues/39)

## Context

The shared Resource Manifest document contract and headless validation path exist, but
users need the first usable cross-platform desktop shell. Startup must be diagnosable
before GUI initialization, and the initial document workflow must never replace an open
document with malformed content or partially replace a file while saving.

## Changes

- [x] Build and install the `resource-manager` SDL3/ImGui executable, deployment INI,
      and runtime dependencies on supported Windows and Linux configurations.
- [x] Require and validate the deployment INI, and establish a once-rotated
      preference-directory `resource-manager.log` before SDL video initialization.
- [x] Add a menu bar, toolbar, and one persistent non-closable editor workspace that
      follows the main viewport during native resizing.
- [x] Add native folder-backed New and native YAML-backed Open while retaining the
      current document after a rejected Open.
- [x] Add canonical Save and Save As through atomic sibling replacement with mandatory
      case-insensitive YAML extensions.
- [x] Cover startup, document workflows, real GUI initialization, rendering, and resize
      through CTest seams that display no error dialogs.

## Out of scope

Schema-bundle configuration, semantic validation, editable Resource forms, history,
recent files, recovery, external-change conflict handling, and the other advanced
workflows remain in follow-up tickets under the Resource Manifest Editor initiative.
