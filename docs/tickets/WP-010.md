## Context

`willpower_import_mpp()` hard-codes `IMPORTED_IMPLIB … .lib` / `IMPORTED_LOCATION … .dll`
under `bin/{Debug,Release,MemCheck}` (MSVC multi-config layout). MPP on Linux is
single-config and outputs to a flat `bin/*.so` — the import logic must branch. The FMOD
section currently does `if(NOT WIN32) FATAL_ERROR` plus `api/*/lib/x64` VC paths.

MPP's own CMake is already cross-platform (verified: WIN32 only gates its GUI app
targets; GLEW is hash-pinned and built from source).

## Changes

- [x] Branch `willpower_import_mpp()` on platform:
      - Windows: keep the current `.lib`/`.dll` + per-config layout.
      - Linux: single-config `IMPORTED_LOCATION "${_mpp_bin}/${stem}.so"`.
- [x] **Verify the exact Linux artifact locations against a real MPP build before finalising**
      the `IMPORTED_*` properties (risk noted in the plan).
- [x] FMOD: keep the explicit `if(NOT WIN32) FATAL_ERROR` for now — the no-op audio
      default already covers Linux. Note the future per-platform `find_*` paths
      (`api/core/lib/linux`, …) in a comment.
