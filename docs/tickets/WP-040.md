# WP-040: Resource Manifest Editor — author file-backed Resources from built-in schemas

- **Status:** done
- **Phase:** Resource Manifest Editor authoring
- **Priority:** P1
- **Difficulty:** hard
- **Blocked by:** WP-039
- **GitHub issue:** [#40](https://github.com/ajare/willpower/issues/40)

## Context

The desktop shell can safely open and save Resource Manifests, but it previously had no
committed editing model. The first authoring slice covers the five source-backed built-in
Resource Types whose forms consist of common identity/source fields and Image options.

## Changes

- [x] Annotate all five built-in `location` properties with the versioned native-file
      editor contract and derive selector filters from catalogued schema bytes.
- [x] Add uncommitted Resource drafts with explicit, valid, namespace-unique names.
- [x] Render Resources in the tree and schema-generated create/edit controls in the
      inspector, with immutable Resource Type display and no migration control.
- [x] Canonicalise selected files, reject missing files and traversal/link escapes, and
      commit portable base-relative paths.
- [x] Add command-stack create, property, rename, and delete edits with undo, redo, and
      continuous-edit coalescing.
- [x] Add headless authoring workflow coverage for all five types, invalid drafts, path
      security, canonical output, Image options, and externally observable history.

## Out of scope

Namespace authoring, composite Resource Types, Resource references, configurable schema
bundles, semantic repair, recovery, and external-change conflict handling remain in
follow-up tickets under the Resource Manifest Editor initiative.
