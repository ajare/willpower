# WP-029: Application — schemas for Program and Material Resources

- **Status:** open
- **Phase:** Resource Manifest validation — built-in schemas
- **Priority:** P1
- **Difficulty:** hard
- **Blocked by:** [WP-025 / #25](https://github.com/ajare/willpower/issues/25), [WP-026 / #26](https://github.com/ajare/willpower/issues/26)
- **Spec:** `docs/specifications/resource-manifest-schema-validation.md` §§8.8–8.9
- **GitHub issue:** [#29](https://github.com/ajare/willpower/issues/29)

## Context

`Program` and `Material` definitions contain the most renderer-specific Resource Manifest structures. Their factories currently parse required dependencies, attributes, mesh layouts, channels, and texture bindings only during Resource creation.

## Changes

- [ ] Add the canonical `Program` schema for Attribs, MeshSpecification, Buffers, Channels, component enums, data-type enums, primitive, storage, indexed, and normalised values.
- [ ] Match the factory's case-insensitive enum behavior.
- [ ] Require Program dependencies with IDs `Vertex` and `Fragment` and a default Definition containing both required sections.
- [ ] Add the canonical `Material` schema for Program dependency and resource/default texture variants.
- [ ] Require `value` for resource textures and forbid a non-empty resource value for default textures.
- [ ] Retain dependency existence/type and resource-texture dependency-ID matching as semantic checks.
- [ ] Register/embed both schemas and add valid and invalid load-time fixtures covering every enum family and conditional branch.

## Files

- `willpower.application/schemas/program.schema.json` (new)
- `willpower.application/schemas/material.schema.json` (new)
- `willpower.application/tests/`

## Acceptance criteria

- Representative valid Program and Material declarations pass during `scan()`.
- Missing required dependencies/sections, unknown fields, invalid enum values, malformed booleans/integers, empty buffers/channels, and invalid texture variants fail during `scan()`.
- Schema enum matching is consistent with the current case-insensitive C++ parser.
- Existing cross-resource semantic checks continue to run after structural validation.
