# WP-032: Application — add a public Resource Schema Catalog API

- **Status:** open
- **Phase:** Resource schema export — catalog API
- **Priority:** P1
- **Difficulty:** hard
- **Blocked by:** [WP-031 / #31](https://github.com/ajare/willpower/issues/31)
- **GitHub issue:** [#32](https://github.com/ajare/willpower/issues/32)

## Context

`ResourceManifestValidator` currently searches a private immutable array generated into `Willpower.Application`. Downstream applications cannot add schemas, and application-specific exporters cannot enumerate or merge the resulting catalog. A public catalog abstraction is needed without exposing Valijson, `yaml-cpp`, or generated implementation types through the DLL boundary.

## Changes

- [ ] Add a public `ResourceSchemaCatalog` abstraction keyed by `(resource type, factory type)` and schema `$id`.
- [ ] Support constructing the catalog from Willpower's embedded built-in bundle and adding one or more external bundles.
- [ ] Support enumeration, exact lookup, default-factory fallback, and deterministic bundle export.
- [ ] Validate bundle versions, hashes, key collisions, schema-ID collisions, and local `$ref` closure while adding a bundle.
- [ ] Make catalog mutation explicit and produce an immutable snapshot for validation/export so concurrent scans cannot observe partial registration.
- [ ] Expose only standard-library and Willpower-owned value types in public headers.
- [ ] Keep schema parsing and validation implementation dependencies private.
- [ ] Add unit tests for merge order, equivalent duplicate content, conflicting duplicates, fallback lookup, malformed bundles, and deterministic export.

## Acceptance criteria

- Public client code can enumerate and export the built-in catalog without including private validator or generated headers.
- A client can add a valid custom bundle and retrieve its schemas by Resource Type and factory type.
- Conflicting keys or schema IDs fail deterministically with actionable diagnostics.
- Catalog snapshots remain valid independently of caller-owned input buffers.
- No YAML, Valijson, or generated catalog type appears in the exported API.
- The full test suite passes on supported Windows and Linux toolchains.
