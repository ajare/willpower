# WP-048: Resource Manifest Editor — harden, verify, document, and ship

- **Status:** done
- **Phase:** Production acceptance
- **Priority:** P1
- **Difficulty:** medium
- **Blocked by:** WP-046, WP-047
- **GitHub issue:** [#48](https://github.com/ajare/willpower/issues/48)

## Context

The complete editor needed one production gate covering its desktop interactions,
automation contract, hostile-input boundaries, operational diagnostics, installation,
headless workflows, GUI smoke path, and user/integrator documentation.

## Changes

- [x] Complete the persistent menu, toolbar, drag-and-drop, selectable diagnostics, and
      inline About/catalog surfaces with command enablement.
- [x] Publish stable exit statuses for usage, configuration, structural and semantic
      validation, containment/filesystem, output/logging, GUI, and test failures.
- [x] Bound manifest bytes, YAML depth/nodes, diagnostics, schema files and aggregate
      content, and dependency traversal while keeping schema resolution local-only.
- [x] Establish and rotate the preference-directory log before GUI initialization and
      record lifecycle, catalog, document, recovery, save, validation, and fatal events.
- [x] Register headless document/authoring/resilience suites and a deterministic real
      SDL3/OpenGL/ImGui smoke test.
- [x] Install the executable, deployment INI, schema bundle, and platform runtime
      dependencies with a relocatable Linux runtime path.
- [x] Complete the glossary, accepted schema/annotation contracts, INI and CLI
      references, workflows, security model, canonicalization warning, statuses, and
      build/run/install guidance.

## Verification

The normal CMake build and CTest suite exercise CLI validation, all headless editor
workflows, startup/logging, schemas, installed artifacts, and GUI smoke behavior on the
supported Windows and Linux configurations.
