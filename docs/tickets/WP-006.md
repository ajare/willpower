# WP-006: Application — drop the gratuitous Windows gate on the FMOD audio backend

- **Status:** done (commit 13e8acc)
- **Phase:** 2 — Willpower.Application sources
- **Priority:** P1
- **Difficulty:** easy
- **Depends on:** —
- **Plan ref:** PLAN.md §Phase 2, item 2
- **GitHub issue:** #6

## Context

`AudioSystem` and `AudioBankResource` gate the FMOD backend on
`WP_PLATFORM == WP_PLATFORM_WINDOWS && defined(WP_APPLICATION_USE_FMOD)`. FMOD ships
Linux/macOS SDKs, so the Windows check is gratuitous. The non-FMOD no-op fallback is a
good pattern and stays the default on all platforms.

The define is produced by the `WILLPOWER_ENABLE_FMOD` CMake option in
`willpower.application/CMakeLists.txt` (line ~50).

## Changes

- [x] Change the gate in `AudioSystem` and `AudioBankResource` from
      `WP_PLATFORM == WP_PLATFORM_WINDOWS && defined(WP_APPLICATION_USE_FMOD)` to just
      `defined(WP_APPLICATION_USE_FMOD)`.
- [x] Keep the non-FMOD no-op as the default on every platform.

## Files

- `willpower.application/include/willpower/application/AudioSystem.h`
- `willpower.application/src/AudioSystem.cpp`
- `willpower.application/include/willpower/application/resourcesystem/AudioBankResource.h`
- `willpower.application/src/resourcesystem/AudioBankResource.cpp`

## Acceptance criteria

- Default build (no FMOD option) is behaviourally identical on all platforms.
- On Windows, building with `WILLPOWER_ENABLE_FMOD` ON still produces the FMOD backend.
- No Windows-specific `#if` remains around the audio backend selection.
