# WP-041: Resource Manifest Editor — organize Resources in flat namespaces safely

- **Status:** done
- **Phase:** Resource Manifest Editor organization
- **Priority:** P1
- **Difficulty:** hard
- **Blocked by:** WP-040
- **GitHub issue:** [#41](https://github.com/ajare/willpower/issues/41)

## Context

File-backed Resource authoring previously operated only in existing namespaces. Moving
or renaming declarations by hand could change dependency targets, create duplicate
identities, or leave schema-invalid empty namespaces.

## Changes

- [x] Present the permanent default namespace and source-ordered flat named namespaces,
      with unique slash-free namespace drafts that commit only with a first Resource.
- [x] Add validated command-stack rename, reorder, move, and delete operations for
      namespaces and Resources, including inferred-name materialization on move.
- [x] Rewrite standard `DependentResources/DependentResource/ref` values transactionally
      on Resource or namespace rename and move, using runtime-compatible same-namespace
      and cross-namespace forms.
- [x] Remove a named namespace with its final Resource as one command, confirm populated
      namespace deletion, and block deletion when known incoming references would dangle.
- [x] Add tree selection, namespace inspector actions, and Resource drag-and-drop for
      reordering and moves.
- [x] Add headless organization coverage for duplicate identities, default protection,
      drafts, ordering, moves, rewrites, deletion rules, and compound undo/redo.

## Out of scope

Composite Resource authoring, inline Resource promotion, custom annotated references,
full semantic validation, schema-bundle configuration, recovery, and external-change
conflict handling remain follow-up work under the Resource Manifest Editor initiative.
