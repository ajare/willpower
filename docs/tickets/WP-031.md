# WP-031: Application — define the Resource Schema Bundle format and package built-in schemas

- **Status:** open
- **Phase:** Resource schema export — bundle contract
- **Priority:** P1
- **Difficulty:** medium
- **Blocked by:** —
- **GitHub issue:** [#31](https://github.com/ajare/willpower/issues/31)

## Context

The canonical Resource Type schemas are currently usable from the Willpower source tree and embedded privately in `Willpower.Application`, but they are not a versioned distributable artifact. External tools need a language-neutral package that identifies every schema by Resource Type and optional definition-factory type, includes all local `$ref` dependencies, and can also be produced by downstream applications.

The bundle describes Resource Manifest declarations; it does not attempt to serialize or reflect C++ `Resource` subclasses.

## Changes

- [ ] Define a versioned, language-neutral Resource Schema Bundle format containing a catalog document and canonical JSON Schema documents.
- [ ] Define catalog fields for bundle-format version, supported Resource Manifest/schema version, Resource Type, factory type, schema `$id`, document location, and document hash.
- [ ] Define entries for catalog-only dependency schemas such as `common.schema.json` and `resource.schema.json`.
- [ ] Specify deterministic ordering and hard errors for duplicate `(resource type, factory type)` keys, duplicate schema IDs with different content, missing documents, invalid hashes, and unresolved local `$ref` values.
- [ ] Specify default-factory fallback and unknown-Resource-Type behavior.
- [ ] Generate a built-in Willpower bundle from the existing canonical schema sources without introducing a second hand-edited source of truth.
- [ ] Make the built-in bundle available from both the build tree and CMake install/package output.
- [ ] Record the bundle contract and compatibility policy in project documentation.

## Acceptance criteria

- A non-Willpower process can enumerate all nine built-in Resource Types using only the exported bundle.
- Every schema reference in the bundle resolves from bundle content with filesystem and network fallback disabled.
- Repeated generation from identical inputs is byte-for-byte deterministic.
- The generated bundle contains hashes that detect modified or substituted schema documents.
- Installing Willpower installs the bundle in a documented, discoverable location.
- Existing runtime validation remains green on Windows and Linux.
