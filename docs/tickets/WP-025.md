# WP-025: Application — add Valijson and an embedded Resource Manifest schema catalog

- **Status:** open
- **Phase:** Resource Manifest validation — infrastructure
- **Priority:** P1
- **Difficulty:** medium
- **Blocked by:** —
- **Spec:** `docs/specifications/resource-manifest-schema-validation.md` §§6.1–6.3
- **GitHub issue:** [#25](https://github.com/ajare/willpower/issues/25)

## Context

Resource Manifests must be validated from their raw `YAML::Node` trees, before `utils::YamlReader` converts scalars and sequences to `StructuredData`. Runtime validation must not depend on deployed schema files or network `$ref` resolution. The canonical JSON Schema files must nevertheless remain directly usable by editors and tooling. Because Utils privately links a static `yaml-cpp`, YAML and Valijson implementation types must remain behind the Utils DLL boundary.

## Changes

- [ ] Add a pinned Valijson dependency and its `yaml-cpp` adapter privately to Utils on Windows and Linux.
- [ ] Add a generic Utils JSON Schema validation operation over `YamlReader`'s parser-owned document; expose only library-neutral schema input and failure records.
- [ ] Add an internal Application `ResourceManifestValidator` with immutable embedded schemas and deterministic validation results.
- [ ] Add a schema catalog keyed by Resource Type, with a future-compatible internal key/API for `(resource type, factory type)`.
- [ ] Add CMake generation that embeds canonical schema files in `Willpower.Application`; generated output belongs in the build tree and is not committed.
- [ ] Resolve all schema `$id`/`$ref` values from the embedded catalog, with no filesystem or network fallback.
- [ ] Validate before `readTree()` conversion without parsing twice; do not expose `YAML::Node` or Valijson types across a DLL API.
- [ ] Add focused tests for embedded schema loading, local reference resolution, and YAML scalar/sequence preservation at validation time.

## Acceptance criteria

- A test validates a raw YAML node with an embedded Draft 7 schema.
- Native YAML scalar types and sequence shapes are visible to the validator.
- `YAML::Node` and Valijson types do not appear in exported Utils or Willpower headers.
- Runtime validation succeeds with schema source files removed from the executable's working directory.
- `$ref` resolution attempts no network access.
- The full existing test suite remains green on Windows and Linux.
