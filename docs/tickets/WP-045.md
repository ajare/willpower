# WP-045: Resource Manifest Editor — load and reload application Resource Schema Bundles

- **Status:** done
- **Phase:** Resource Manifest Editor schema deployment
- **Priority:** P1
- **Difficulty:** hard
- **Blocked by:** WP-041, WP-044
- **GitHub issue:** [#45](https://github.com/ajare/willpower/issues/45)

## Context

The editor always constructed its embedded built-in catalog and restricted creation to
nine built-in Resource Types. Application bundles, annotation failures, unknown payload
limitations, and atomic configuration reload were not part of deployment.

## Changes

- [x] Extend the deployment INI with an optional complete `baseBundle` and repeated,
      ordered `bundle` settings resolved relative to the INI directory.
- [x] Use embedded built-ins only without a configured base and reject duplicate editor
      lookup keys, malformed bundles, incomplete catalogs, and malformed annotations.
- [x] Complete the versioned validation-neutral file and Resource-reference annotation
      vocabulary, including file filters, allowed Resource Types, and manifest scope.
- [x] Generate application Resource and default Definition forms for the documented
      scalar subset entirely from bundle data, while retaining unsupported forms
      read-only.
- [x] Preserve unknown declarations and Definitions through safe common operations and
      expose explicit unknown/unsupported limitation warnings.
- [x] Reload the INI and all bundles through an isolated candidate, publishing only when
      the candidate loads and validates the open Resource Manifest.
- [x] Add `--verify-schemas`, a schema integration suite, startup command coverage, and
      documentation for configuration, offline trust boundaries, and reload behavior.

## Out of scope

Semantic repair/save gating, base-directory migration, external file conflicts,
recovery, recent files, and final production hardening remain in WP-046 through WP-048.
