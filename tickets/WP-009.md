# WP-009: cmake/Helpers.cmake — platform-aware target helpers

- **Status:** open
- **Phase:** 3 — CMake cross-platformization
- **Priority:** P0
- **Difficulty:** medium
- **Depends on:** WP-008
- **Plan ref:** PLAN.md §Phase 3, item 2
- **GitHub issue:** #9

## Context

`cmake/Helpers.cmake` contains MSVC-only constructs that break GCC/Clang:
`willpower_target_defaults` sets `/MP`, `MSVC_RUNTIME_LIBRARY`, and `PDB_OUTPUT_DIRECTORY`;
`willpower_enable_sdl_checks` passes `/sdl`; `willpower_deploy_runtime_dlls` stages
`$<TARGET_RUNTIME_DLLS>` (an MSVC-only genex).

## Changes

- [ ] `willpower_target_defaults`: generator-express / guard the MSVC-only properties
      (`MSVC_RUNTIME_LIBRARY`, `PDB_OUTPUT_DIRECTORY`, `/MP`, `/fsanitize=address`) behind `if(MSVC)`;
      add `-Wall -Wextra` for GNU/Clang.
- [ ] `willpower_enable_sdl_checks`: no-op off MSVC.
- [ ] `willpower_deploy_runtime_dlls`: keep `$<TARGET_RUNTIME_DLLS>` staging on MSVC;
      on GCC/Clang rely on build-tree RPATH (CMake default) and add a post-build copy of
      linked `.so`s next to test executables only if RPATH proves insufficient.

## Files

- `cmake/Helpers.cmake`

## Acceptance criteria

- All modules configure and build on MSVC and on Linux (GCC + Clang).
- Windows runtime DLL staging behaviour unchanged.
- Linux test executables find `libWillpower.*.so` without manual `LD_LIBRARY_PATH`.
