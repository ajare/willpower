# WP-005: Application — portable Scheduler/SchedulerTask timing (QPC → steady_clock)

- **Status:** done (commit 67e9465)
- **Phase:** 2 — Willpower.Application sources
- **Priority:** P0 (hard blocker; the classes `#error` off-Windows)
- **Difficulty:** hard
- **Depends on:** WP-001 (`ASSERT_TRACE` used by SchedulerTask.cpp)
- **Plan ref:** PLAN.md §Phase 2, item 1
- **GitHub issue:** #5

## Context

`Scheduler.h` and `SchedulerTask.h` `#include <windows.h>`, store `LARGE_INTEGER`
members (`mFrequency`, `mStartTime`), and are wrapped in
`#if WP_PLATFORM == WP_PLATFORM_WINDOWS` with a literal
`#error "…supported only on Windows."` in the `#else` branch. `Scheduler.cpp` /
`SchedulerTask.cpp` use `QueryPerformanceFrequency()` / `QueryPerformanceCounter()`
for the µs timeslice budgeting.

## Changes

- [x] Replace the QPC time source with `std::chrono::steady_clock` (ns resolution on glibc is fine for µs budgeting).
- [x] Add a small internal helper (e.g. `HighResTimer` in a new `src/PlatformTimer.{h,cpp}`) so the class bodies stay clean.
- [x] Delete `<windows.h>`, the `LARGE_INTEGER` members, and both `#error` guards — the classes become unconditional.
- [x] Keep the budget-scaling algorithm byte-for-byte (identical arithmetic, no re-tuning).

## Acceptance criteria

- `Scheduler` / `SchedulerTask` compile and link on Linux and Windows with no platform `#if` around the classes.
- No `windows.h` include remains anywhere in the module.
- Task ordering and µs budget-scaling behaviour match the Windows implementation (verified by WP-007).
